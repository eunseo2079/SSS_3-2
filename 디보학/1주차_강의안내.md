# 1주차
### AI sys은 *정보시스템* 위에서 동작한다
ai 서비스는 네트워크, 서버, 데이터, 애플리케이션 위에 얹힌 하나의 층 

<img width="503" height="254" alt="image" src="https://github.com/user-attachments/assets/bc2d9816-7bca-4c09-9dfc-505fdc6e34f0" />

- **ai 모델, 서비스**-> **ai 고유의 위협** 받음
- **애플리케이션, api / 데이터, 저장소 / 서버, 엔드포인트 / 네트워크, 계정** -> **실제 침투가 일어나는** 곳임
  - ai 고유의 위협? 프롬프트 인젝션, 데이터 오염, 모델 탈취 등
  - 실제 침투? 계정 탈취, 인증우회, 패치되지 않은 취약점 등
  - (ai를 노린 공격 또한 아래 네 개의 취약점 통해 들어옴)
 
### AI를 노린 공격은 어디로 들어오는가?
- **적대적 공격**: 미세한 입력 조작 -> 모델의 판단 뒤집음
- 성립조건: 입력경로 (api. 업로드 기능)에 접근 가능해야
- **데이터 오염**: 학습, 튜닝 데이터에 악의적 표본 섞음 -> 모델 왜곡
- 성립조건: 데이터 수집경로, 저장소에 쓰기 권한 확보해야
- **모델, 프롬프트 탈취**: 가중치/ 시스템 지시문 빼내는 공격
- 성립조건: 모델 파일이 있는 서버, 저장소에 접근 or API 남용해야

--> **공통점**: 공격 이름은 AI지만, 성립 조건은 계정, 권한, 서버, 네트워크의 취약점
